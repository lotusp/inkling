# Inkling 核心价值

状态：用户目标已明确，优势与效果待验证。更新日期：2026-11-13。

Inkling 面向希望把实践经验和学习所得转化为个人技术文章的作者。核心价值是帮助作者形成可解释的判断，把判断准确表达出来，并让这次理解成为下一次思考可以使用的资产。

## 用户与任务

首要用户是有技术实践或持续学习经验、愿意参与思考与修改的个人中文作者。首个验证场景是实践复盘或技术取舍分析，交付个人博客和技术社区文章。

核心任务：当我有一些经验、资料和模糊判断时，帮助我找到值得回答的问题，辨认事实和假设，检验反例，并组织成我愿意认可和负责的文章。

个人洞见可以是特定情境下的解释、取舍或边界，也可以是对旧看法的修正；不要求每篇文章都有全球首次提出的结论。

## Elevator Pitch

Inkling 是个人技术作者的思考与写作伙伴。当你有一段实践经验、一个疑问或尚未成形的判断时，它通过有针对性的讨论、资料对照和反例检查，帮助你把想法想清楚，再把自己的理解组织成文章。每次写作留下的观点、依据和修改都会保存下来，支持下一次思考。

## 四项价值假设

| 编号 | 作者得到的价值 | 最小产品机制 | 验证证据 | 失败信号 |
| --- | --- | --- | --- | --- |
| V1 | 更清楚自己要解释什么、为什么这样判断 | 从经历提炼问题，区分观察与推断，保留反例和未知 | 协作前后作者能否独立解释问题、结论与边界 | 只能重复模型结论，追问造成负担 |
| V2 | 关键技术论证有明确依据和适用范围 | 原文定位、版本与环境条件、证据和论断关联 | 已知冲突检出、引用支持关系、条件遗漏与误报 | 堆积引用却不支持结论，错误套用版本 |
| V3 | 文章表达作者真正想说的内容 | 局部差异、版本恢复、意图标记、经历与建议分离 | 原意保留、作者重写负担、对成稿的认可 | 擅自增加立场、编造经历、为了流畅改变含义 |
| V4 | 下次写作可以继承过去的理解 | 经确认的经验与观点、变化理由、可修改的偏好 | 后续项目中旧资产被找回并实际使用 | 记忆噪声增加，过时观点束缚新的判断 |

## 差异化如何成立

竞品已经提供风格指南、知识库、引用与审阅；Essay.app 等产品也明确支持思考。因此 Inkling 的优势只能通过特定作者、特定任务和持续使用表现证明。

产品应与通用 Agent 加现有编辑器、Essay.app、Heptabase 和 Lex 等实际替代方案比较。若现成组合在理解、原意保留和使用负担上已经足够好，应优先提供连接或协作方法。

可积累的优势来自可靠的正文与依据关联、低负担的协作方法、个人经验和观点演变的有效找回。单一提示词、自动总结、图谱或某个 Agent 框架不独立构成优势。

## MVP 与范围

最小承诺：支持一位作者将一个模糊技术想法推进为自己认可、能解释依据的文章，并在下一次写作中找回有用经验。

必要能力是输入、讨论、观点与依据关联、大纲、局部编辑与版本、审阅、Markdown 导出，以及手动确认的最小长期积累。未成文的探索笔记也是有效产物。

本阶段不建设热点仿写、批量内容生产或流量优化。首个博客接口在思考与写作闭环后逐步接入；复杂画布、大规模记忆和多代理协作按验证需要引入。具体范围与路线由[协作设计](thinking-partner-product-design.md)维护。

## 衡量价值

北极星指标候选：每月完成的、经作者认可且能解释依据的文章项目数。同时观察有价值的探索笔记，避免迫使所有思考立即成文。

| 观察维度 | 如何记录 |
| --- | --- |
| 理解改善 | 作者用自己的话解释问题、判断和限制；保留前后实例 |
| 论证可靠 | 同领域读者检查重要论断、依据和条件，记录漏报与误报 |
| 原意保留 | 比较修改前后含义，记录作者认可和拒绝的原因 |
| 操作负担 | 区分深入思考时间与查找、搬运、无效重写时间 |
| 连续使用 | 观察作者是否主动回来、旧经验是否在新项目有用 |

生成字数、对话轮数、AI 建议采纳率、搜索流量和 AI 检测率不作为核心质量指标。作者拒绝一个不合理建议，也可能是成功的协作。

首轮验证使用真实完成稿和搁置稿，随后进行少量作者的形成性测试。样本和门槛在每次实验前明确，结果保留反例，不把小样本偏好外推为市场结论。

## 当前已知与未知

已明确的是作者的目标和当前产品边界。尚未证明的是追问是否带来理解改善、结构是否增加管理成本、记忆是否真正有用、独立应用是否优于现有组合，以及其他作者是否愿意持续付费。

未决问题及其验证入口见[开放问题](open-questions.md)。价值定义发生改变时，应补充证据、记录决策并同步 MVP 与验收，不能只改宣传语。
