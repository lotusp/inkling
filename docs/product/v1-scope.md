# Inkling V1 功能范围与交付设计

更新日期：2026-11-16。状态：完整首版范围提案，尚未实现。作者已提出 MVP 尽量覆盖第一版本的完整功能，优先形成清晰合理的设计。本文是 V1 范围的主要维护位置，替代早期把文风学习、连续使用和首个博客接入放到后续版本的安排。

## 版本目标

V1 支持作者在单台 Mac 上持续完成中文技术写作。作者能够从一个想法开始，收集资料、讨论判断、组织文章、按个人风格协作编辑、检查依据、导出并发布到自己的博客，再在下一篇中复用经验和材料。

一次研究可以停留在笔记或讨论。正文可以从空白、导入稿或已有文章开始，阶段之间允许自由往返。产品价值沿用[核心价值](core-value.md)中的理解改善、论证依据、作者原意和长期复用。

AI 辅助开发用于提高实现和迭代速度。功能范围按用户完整任务确定，完成状态以实际入口、数据保存、异常处理和使用验收判定。文档、原型和已有 SDK 分别提供设计或实现基础，具体功能需要接入后验证。

## V1 功能清单

以下各项都属于 V1 最终交付，开发顺序见后文。

| 编号 | 能力 | V1 包含的功能 | 完成后的实际使用结果 |
| --- | --- | --- | --- |
| F-001 | 工作空间与文章管理 | 首次启动、创建与打开文章、重命名、归档、标签、搜索、回收站及恢复 | 找到旧稿并继续编辑，误删可以恢复 |
| F-002 | 正文编辑 | 标题、段落、列表、引用、链接、代码块、图片、表格、公式、基础 Mermaid 代码与预览；撤销重做、自动保存、导出预览 | 在一个编辑器内完成常见技术文章，中文输入与粘贴稳定 |
| F-003 | 文档内 AI Chat | 持续对话、历史会话、新建讨论、选区引用、附加资料、流式响应、取消、中途纠正、失败重试 | 围绕当前文章或选中段落持续讨论，并清楚知道使用了哪些上下文 |
| F-004 | 灵感与资料 | 快速记录、文本与 Markdown 导入、URL 获取、文本型 PDF 解析、图片附件、摘录与批注、标签、项目关联和全文查找 | 个人观察与外部资料有明确来源，记录后能在写作时找回 |
| F-005 | 研究与观点形成 | 问题澄清、定向搜索、资料比较、原文定位、观点与依据关联、假设和反例、技术版本及适用条件 | 作者能解释判断从何而来，并保留未解决问题 |
| F-006 | 大纲与协作写作 | 从讨论或草稿整理大纲、调整章节、分节写作、按请求起草全文、续写、压缩、扩展与选区改写 | 大纲与正文可往返，候选内容可逐步插入和修改 |
| F-007 | 作者风格 | 导入自己的样文、生成可编辑风格说明、按文类建立档案、文章级选择、禁用表达和例外 | 同一作者的教程与复盘可采用不同表达偏好，作者可修正规则 |
| F-008 | 审阅与修订 | 论证、引用、术语一致性、重复内容和风格检查；建议定位正文，查看理由与差异，接受、拒绝或手改 | 发现具体问题并完成修订，重要结论可回到依据 |
| F-009 | 文章版本 | 自动恢复点、命名版本、版本比较、恢复旧内容、候选基线校验、并发标签页冲突提示 | 能比较和恢复修改，旧建议不会覆盖作者的新编辑 |
| F-010 | 个人知识与记忆 | 已确认的经验、观点、术语与偏好；引用相关旧稿；记录观点改变的原因；修改、撤回、删除和导出 | 第二篇文章能使用第一篇积累的理解，作者能管理长期记忆 |
| F-011 | 导出与博客交付 | Markdown、HTML 与附件包；一个博客的草稿、预览、确认发布和更新；发布记录与失败核对；社区格式复制或导出 | 一篇文章从本地成稿交付到作者实际博客，后续修改能对应远端文章 |
| F-012 | 本地运行与维护 | 模型配置、凭据保存、上下文范围提示、任务进度和成本、运行中断继续、离线编辑、备份恢复、数据导出与日志入口 | 在本机持续使用，重启或请求失败后能找回内容与处理任务 |

F 编号作为后续功能规范、实现和验收的引用。本表给出范围，具体数据与状态契约在各功能进入开发前细化。产品背景可参考[功能模板](../templates/feature.md)，可执行行为与验收进入 OpenSpec change，按[开发 Harness](../engineering/harness.md)验证、归档后成为 Living Spec。

## 默认交互与入口

当前可操作演示见[交互原型 V2](../prototypes/README.md)。原型使用示例回复与模拟发布，覆盖主要交互，不代表本篇全部功能已经实现。

主界面采用正文与 Chat 两栏。顶部放文章标题、保存状态、版本、导出和发布入口；左侧可展开文章列表、大纲、资料；右侧 Chat 可调宽度和收起。

研究、大纲、表达和审阅通过自然语言、选区快捷操作或上下文按钮启动。编辑器始终保留当前稿件和位置，任务完成后在侧栏展示结果或在正文位置展示建议。

| 作者动作 | 系统响应 |
| --- | --- |
| 选中段落后发问 | 固定本次选区与文章版本，显示上下文标记 |
| 在 Chat 中讨论一个新想法 | 保存讨论，可提炼为笔记、观点或正文候选 |
| 请求补充依据 | 发起研究任务，展示来源、进度和可取消入口 |
| 请求改写 | 显示候选及差异，支持替换选区、插入或放弃 |
| AI 生成期间继续写作 | 保留作者编辑，采纳时校验原位置与基线 |
| 接受某种表达偏好 | 先用于当前文章，需要时明确保存为长期规则 |
| 选择发布 | 显示具体文章版本、目标和格式预览，再执行所选动作 |

聊天历史、文章内容和长期记忆有独立生命周期。新建讨论可以关联当前文章，删除正文不会自动删除其讨论历史。进入项目时恢复最近编辑位置和关联会话。

## 功能深度与具体约束

编辑器覆盖常见技术文章格式。公式和 Mermaid 在预览中渲染，导出时给出源代码或目标支持的形式；目标平台无法保留的格式显示转换结果。V1 先确定一套正文权威表示，避免两个格式独立编辑产生歧义。

资料导入优先支持文本型 PDF。扫描件保留为附件并说明解析状态，OCR 与音视频转录作为扩展。网页无法读取时允许粘贴原文，保存获取状态和来源信息。

风格学习产生作者可以编辑的规则与样本引用。V1 不依赖模型微调，少量样文或手工规则也能开始使用。作者经验、外部观点与表达规则分别保存。

记忆具备明确的保存和撤回入口。跨文章推荐只使用作者允许的资料范围，引用旧经验时显示出处。已有观点发生变化时记录新旧关系，由作者决定如何表达。

搜索、读取、讨论和审阅有调用预算与停止条件。审阅结论可被作者推翻，反馈记录到具体建议；生成内容与未接受建议不自动成为作者长期立场。

## 发布是 V1 的一部分

V1 应打通作者实际使用的一个博客。目标系统确定后，核验其草稿、图片、发布、更新与查询能力，并在功能规范中写明真实契约。Git 博客与 API 博客的操作入口和完成状态按各自实现定义。

导出、建立远端草稿、公开发布和更新旧文是明确的用户动作。发布确认绑定当前内容、附件和目标。正文修改后，旧确认需要重新检查。结果不明时先核对远端，保留已知状态与处理入口。

对于技术社区，V1 提供可检查的 Markdown／HTML 格式交接。各社区的自动直发按具体官方接口和账号能力逐个接入，不以未经核验的平台列表定义完成度。

首个博客尚未确定，是发布连接器实现前的具体依赖。可先完成统一预览、导出和连接器契约，最终交付仍需用真实目标验证发布和更新。

## Agent 与技术能力的对应关系

| 技术能力 | V1 用途 |
| --- | --- |
| 单个主 Agent | 持续讨论、选择工具、组织候选成果、响应作者干预 |
| 内置 Skills | 探索、研究、大纲、表达、风格应用、审阅和发布准备的方法 |
| 工具接口 | 本地资料与正文访问、候选写入、网络检索、模型和博客适配 |
| MCP Client | 有具体资料连接需求时使用，与原生工具共用范围和调用记录 |
| Session 与 Run | 对话持续性、任务状态、预算、取消和恢复 |
| 轻量领域关系 | 问题、观察、论断、证据、条件、段落和版本之间的关联 |
| 本地持久化 | 内容、任务、版本和记忆的可靠保存，具体介质经 POC 确定 |

功能完整度通过作者可完成的任务衡量。subagent 数量、向量数据库和框架数量按实际实现需要选择。独立审阅可以使用同一个运行时的隔离上下文调用。

## V1 之后的扩展

上云、多设备同步和多人实时协作遵循既定长期方向。独立桌面安装包、移动端捕捉、OCR 和音视频转录、更多博客适配器、自动追踪资料版本并复核旧文，按后续真实需求安排。

当前产品定位继续排除追热点、热门文章仿写和批量流量内容生产。这个边界来自作者的目标，而不是实现速度。

## 同一版本内的实施顺序

以下各批都属于 V1，前一批完成可以开始自用并收集反馈，V1 发布以整体范围和验收结果为准。

| 批次 | 实现内容 | 阶段可用结果 |
| --- | --- | --- |
| A 设计与技术验证 | 工作台交互、正文表示、文件与 SQLite 比较、运行时、版本与工具契约 | 固定影响后续实现的选择，完成风险点小验证 |
| B 编辑与对话 | F-001／002／003／009，F-012 的启动、配置与持久化 | 本地写稿、讨论、修改和找回内容 |
| C 资料与论证 | F-004／005／006／008 | 收集材料、检验判断、组织与审阅文章 |
| D 个人积累与交付 | F-007／010／011，补齐 F-012 的备份与恢复 | 按个人风格连续写作，真实博客发布并更新 |
| E 完整使用验收 | 正常入口、异常恢复、跨文章连续使用与格式核验 | 可交付的单机 V1 |

在拆出功能任务和完成技术验证后估算工期，使用实际吞吐量调整计划。用户观察、原型验证和工程实现可以并行推进，形成性访谈不是启动开发的统一前置审批。

## V1 验收场景

1. 从一句实践观察开始，加入个人笔记、官方网页和文本 PDF，形成带依据与条件的大纲。
2. 在正文与 Chat 中完成文章，使用代码、图片、表格、公式或图示，并应用所选风格规则。
3. AI 建议返回前继续手动编辑，接受建议时保留新内容，能比较与恢复历史版本。
4. 故意放入引用不支持的论断和版本冲突，检查审阅是否定位问题，并记录漏报和误报。
5. 将经确认的经验与偏好用于第二篇文章，能够找到来源、修正观点并撤回记忆。
6. 导出文章及资源，向真实博客建立草稿、预览、发布与更新；超时或失败可核对，避免重复创建。
7. 关闭浏览器、断网、重启服务及 Mac 休眠后，验证内容保存、任务状态和继续入口。
8. 在新目录恢复备份，验证正文、资料、版本、会话和记忆可用，凭据处理符合设计。

每项验收记录应用和依赖版本、实际输入、结果与限制。发布、修改主稿和记忆写入应使用真实产品入口，测试替身只用于可控的失败场景。

## 开发前优先细化的设计

先补齐工作台交互与状态、正文和资料的权威格式、版本与修改协议、Chat 上下文与任务生命周期、风格记忆确认、首个博客适配六项规范。它们共同决定各模块如何合作。

当前仍有三个具体待确认项：作者实际博客系统、远程模型与资料发送要求、目标 Mac 的硬件和系统版本。它们分别在连接器、模型和打包验证前处理，其余功能可以继续设计和实施。
