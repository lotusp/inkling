# 本地存储性能验证

日期：2026-11-17。范围：C02 开发分支的当前实现；不是跨设备性能承诺。

环境：Apple M1 Pro、macOS Darwin 25.6.0、arm64、Node 22.22.2。真实 better-sqlite3，WAL / synchronous FULL / fullfsync ON。通过本机 HTTP 认证接口连续保存，每组预热 2 次，再测量 30 次；样本包含中文段落、混合强调、小标题、列表和多行代码，JSON UTF-8 大小精确为 60 KiB / 2 MiB。记录包含请求传输与响应解析，不包含客户端生成/编码请求正文的时间。

| 指标 | 实测 p95 | 既定门槛 | 结果 |
| --- | --- | --- | --- |
| 60 KiB 保存 API | 12.08 ms | ≤250 ms | 通过 |
| 2 MiB 保存 API | 171.68 ms | ≤1000 ms | 通过 |
| 普通稿件时服务进程事件循环延迟 | 10.82 ms | ≤50 ms | 通过 |

事件循环使用服务进程内 monitorEventLoopDelay，1 ms 分辨率；普通稿样本数 43。最大稿的事件循环 p95 94.18 ms、最大 169.74 ms，设计未对最大稿设置 50 ms 门槛，不应把普通稿的通过结论推广过去。当前同步适配器满足本轮既定门槛，未改为 worker；如增加并发或更复杂稿件，应重新评估大稿阻塞。

累计 69,075,028 字节历史后，重新打开与逐版 hash 扫描耗时 883.54 ms；这是额外观测，不是既定启动 SLO。启动扫描时间随历史增长，接近容量上限时需再次测量。两组各 30 次不覆盖所有节点数/深度组合，也不证明断电、物理介质故障或 Linux 性能。

运行：

```bash
corepack pnpm test:storage-performance
```

命令对任一既定门槛失败返回非零退出码；使用隔离空间并自动清理，没有产品 HTTP 性能/故障管理开关。最初纯文本测量保留为辅助基线，以上中文结构化样本是最终结果。证据见 [性能日志](../../openspec/changes/archive/2026-11-17-persist-article-revisions/evidence/storage-performance.log)。

## C03 文章库回归（2026-11-18）

相同目标 Mac、Node 和 SQLite 耐久配置下重新执行正式脚本；全部使用临时工作空间。保存 API 的 60 KiB / 2 MiB p95 分别为 **12.28 ms / 102.13 ms**，门槛分别为 250 ms / 1000 ms；普通稿事件循环 p95 **10.06 ms**，门槛 50 ms。最大稿事件循环 p95 89.72 ms，不受普通稿门槛约束。69,075,028 字节修订历史的重开与 hash 扫描为 936.5 ms，仅为观测。

新增文章库夹具通过真实认证 API 新建 1,000 篇文章，其中活动 900、归档 50、回收站 50。活动状态的中文标题片段 + 精确标签过滤匹配 300 篇；首屏读取 30 次和完整 15 页（每页 20 条）共 45 次样本，p95 **1.79 ms**、最大 3.24 ms，满足预先约定的 250 ms 门槛。最大响应 3,843 字节，原始响应不含正文，全部匹配 ID 无遗漏或重复。

测试反映单机顺序操作，未覆盖多用户并发、冷缓存或所有历史规模，不作为跨设备性能承诺。脚本保留所有既有保存门槛，任一失败非零退出。实际命令与结果见 [C03 性能日志](../../openspec/changes/manage-article-library/evidence/library-performance.log)。
