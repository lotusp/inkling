# 写作台 V3：文章库、灵感、资料与本文大纲评审

**建议保留文章库和可追溯的资料，取消独立的「灵感」页面，把本文大纲移回稿纸。** 灵感需要随时记，资料需要在写作时找得到，大纲需要跳到眼前文章的某一节。现在三个入口并排在文章库底部，作者每次都要先想到「打开文章库」。此外，读大纲会改变讨论选段，整理另一篇稿会切换列表，这两处隐含的动作比多一个按钮更容易打断写作。[当前文章库截图](evidence/writing-desk-v3-11d2f66/inkling-writing-desk-v3-library.png)

## 四项能力在 V1 的位置

| 能力 | V1 取舍 | 从哪里进入、完成后得到什么 |
| --- | --- | --- |
| 文章库 | 保留。负责查找、新建和整理稿件。 | 顶栏「文章库」始终打开文章列表。点标题切稿，点行末「⋯」才出现重命名、改标签、归档和移入回收站。 |
| 灵感 | 保留快速记录，省去独立页面和录入前的分类。 | 左栏可切到独立的「素材」视图，第一项是「随手记」。写一句即可保存，可以没有文章，也可以一直只是一条笔记。需要成文时再选「用这条开始写」。 |
| 资料 | 保留。它支撑 V1 的依据核对与跨稿复用。和随手记共用素材入口，每条保留来源。 | 平时在「素材」里收集；写作时从讨论框「附加资料」搜索并选用。查看摘录可以回到原文。移除本篇引用后，原资料仍可供下篇使用。 |
| 本文大纲 | 保留章节导航与起草结构，取消文章库中的入口及单独维护大纲的负担。 | 在稿纸标题附近打开「大纲」，从现有章节生成，选章节返回正文。空白稿可先列标题，AI 建议经采用后才成为正文标题。 |

左栏可以共用空间，文章与素材各有自己的列表、搜索和新建动作。打开文章库默认见稿件；进入素材后是独立视图，明确显示「返回文章」。选资料时则回到发起选择的讨论。资料、笔记和正文之间的关系可以随写作逐渐建立。Ulysses 的 Material Sheets 给出了类似取舍：研究材料可以独立保存，默认排除在成稿导出之外。[Ulysses 官方说明](https://help.ulysses.app/en_US/first-steps-library-editor)

## 文章库操作走查

| 作者任务 | 原型中的体验 | 建议 |
| --- | --- | --- |
| 新建并开始写 | 「新建」直接创建并聚焦标题，流程短。标题预填「未命名文章」；当前主题筛选会被清空。 | 保留一步新建，标题允许留空，直接写正文。「未命名文章」作占位。新建后显示新稿，返回此前的列表时恢复原查询。 |
| 找一篇记得几个字的文章 | 原型可以按范围与主题筛选，但没有标题搜索。找某主题的归档稿要打开筛选、选范围和主题，再点「查看文章」。只有两篇示例稿时不容易看出这项成本。 | 库内首行提供「搜标题或标签」。默认按最近编辑排序，范围用「写作中 ▾」选择，选择即更新；无结果时给「清除条件」，也可明确扩大到全部非回收站文章。普通行只显示标题，遇到同名或未命名稿再用修改时间区分。 |
| 改名、改标签 | 标题能在稿纸上修改，列表行菜单缺少改名入口。「设置分类」需要按行输入，移除正在筛选的分类还会清空整个主题条件。 | 「⋯ → 重命名」在原行编辑，沿用稿纸的同一标题。「编辑标签」优先选已有标签，也可新建。移除当前筛选标签后，该稿退出结果，列表继续保留原条件。输入中文选词时，回车先确认候选。 |
| 归档或搁置 | 「暂时搁置」和「归档留存」都进入已归档。正在写 A，顺手归档 B，列表会跳到已归档，稿纸仍显示 A。 | 只保留「归档」。已有搁置原因仍可查阅。整理其他稿时留在原列表，行消失，反馈「已归档《B》 · 撤销」。归档**当前稿**时让稿纸明确变为只读，可直接「移回草稿」。发表状态继续作为标记和筛选条件，已发表的文章仍可编辑或归档。 |
| 误删和恢复 | 确认框能说明文章、去向及正文历史会保留；回收站区分「恢复到草稿」「恢复到已归档」。确认后列表会跟着文章跳转。 | 保留确认、原位置恢复和明确的按钮文案。处理其他稿时原列表不跳转。删除当前稿后回文章列表；在回收站恢复时留在回收站，反馈提供「查看已恢复文章」。窄屏同样只在作者明确打开稿件时切到正文。 |

这部分评审针对 [V3 HTML](../prototypes/inkling-writing-desk-v3.html)。标题与标签查找、重命名和原位置恢复已有 [C03 文章库契约](../../openspec/changes/manage-article-library/specs/article-library/spec.md)。建议原型对齐这些能力。iA Writer 的文件列表也采用单击打开、上下文菜单重命名的分工。[iA Writer 官方导航说明](https://ia.net/writer/support/library/navigation)

## 素材和大纲的三个交互边界

1. **存下想法时保留是谁说的。** 原型「存为灵感」只复制 AI 回复的正文，来源和引用随之丢失，之后与作者手记看起来相同。「插入正文」还会把整条内容追加到文末。建议同一入口按来路自动记录「我的随记」「来自讨论」或外部出处，来自讨论可跳回原消息。默认只收藏，明确选择写入时才插入光标处或指定段落。
2. **收藏资料和使用资料应有不同的反馈。** 原型的「添加资料」只有标题与摘记。资料列表中的复选框一勾就改变本文关联，而「查看资料」打开的也是这份可勾选列表。建议保存链接或附件时自动带上出处，摘录保留可定位的原文位置；点资料行只阅读。从讨论进入选择器时写明「用于《当前文章》」，选中的资料可见、可移除。同一来源跨文章复用，作者不必再复制一份。
3. **阅读导航不应替作者选择讨论对象。** 原型大纲从小标题生成，但跳转函数还会把标题设为讨论选段。建议点标题只定位，短暂高亮，保留讨论原有范围。需要针对该节发问时再显式「讨论这一节」。短稿默认收起；长稿在标题旁提供可发现的「大纲」入口。先列大纲的作者可以在空稿中插入章节标题，分节写作和后续调序都围绕同一份稿件完成。

## 下一轮复评任务

- 正在写 A 时，按标题找到 B，改名后归档。作者应一直知道眼前是哪篇稿，原搜索条件仍在，能撤销归档。
- 一篇文章都没有时记一句疑问，再存一个来源链接。稍后只给新文章附上链接；另一篇能引用同一来源，个人疑问仍独立存在。
- 在 AI 回复上点收藏，再与作者手写的笔记一起找回来。两者能看出不同出处，正文不会因为收藏而变化。
- 讨论已引用甲段时，点大纲跳到乙节。正文显示乙节，讨论继续引用甲段。窄屏关闭大纲后返回刚定位的位置。
- 把一篇归档稿移入回收站再恢复。恢复到已归档，作者可查看正文与历史，并主动决定是否继续编辑。
