# 写作台 V3 原型评审

2026-11-18，评审对象为提交 `11d2f66` 的[写作台 V3](../prototypes/inkling-writing-desk-v3.html)。本次走查了[首屏](../prototypes/inkling-writing-desk-v3.png)、[文章库](../prototypes/inkling-writing-desk-v3-library.png)和[版本比较](../prototypes/inkling-writing-desk-v3-history.png)，并用临时数据在 Node 中执行了原型的切稿、生成候选、采用、搜索和恢复处理逻辑。页面元素使用内存替身，未连接个人稿件、模型或博客。本地文件受内置浏览器访问限制，本轮未做浏览器点测、真实输入法测试或作者访谈。

**结论：先修选区和撤回，再修切稿，最后调整版本入口。** 三项任务中，前两项会让作者重写或重找刚才的内容，第三项能完成，但要求作者知道版本放在哪里、怎样识别日期。

## 切到另一篇做对照，再回来续写

**通过条件。** 在本文后半段写作，讨论框里留一个未发送问题。通过文章库打开另一篇，返回后仍能在原处续写，并接着编辑原问题。另一篇的讨论保持独立。

**结果：未达到。** 原型的 `switchTo` 既重置正文滚动位置，也清空讨论输入框。用 A、B 两篇稿件复核，将 A 的滚动值设为 680，问题写为「这条观察够吗？」，A → B → A 后读到滚动值 0、问题为空。已发送的消息仍属于原文章。这个区别使作者即使看见熟悉的讨论，也找不回刚写到一半的问题。

**建议。** 点文章标题即切换，自动记住每篇的编辑位置、每个讨论的输入草稿。返回时恢复原状态，无须增加「保存问题」按钮或切稿确认框。正文位置可以沿用 [C03 的位置恢复约定](../../openspec/changes/manage-article-library/specs/article-library/spec.md)：同一修订恢复，位置失效时安全回退。这里记录的是演示原型行为。

## 只改中间一句，再撤回这次修改

**通过条件。** 在一个三句段落里划选中间一句，采用后首尾两句逐字保留。即使作者事前没有手动存版，也能回到采用前的内容。

**结果：未达到。** `selectionTool` 只保留段落标识，`propose` 取整个段落，`apply` 写回整个段落。按钮叫「改写这段」，候选也会展示整段原文；可作者拖选的一句话和实际写入范围仍然不同。用下面的稿件运行处理逻辑，把可编辑候选改为作者想要的一句话后采用：

| 采用前 | 希望只替换的内容 | 实际采用后 |
| --- | --- | --- |
| 昨天做过实验。**网络中断时我仍能写。** 今天再测一次。 | 断网后，我还能继续写。 | 断网后，我还能继续写。 |

另做了两个对照。生成候选后再手改正文，旧候选被拦截，作者的新字得到保留。若三句原文是上次存版后刚写的，随即采用候选，历史列表内没有任何版本含有这三句完整原文。这限定了原型说明中「采用修改后回到历史可以找回原稿」的适用范围。

**建议。** 改写可参考整段，写回只替换高亮选区。若本期仍按整段处理，打开候选时就在稿纸上高亮整段，把采用按钮写成「替换整段」。采纳时自动保留修改前稿，成功反馈就地提供「撤销」。复评时用上述三句重复操作，检查首尾两句，再撤销并逐字比对全文。保留现有过期检查。

## 找到昨天的稿子，比较并恢复

**通过条件。** 作者只记得大约的日期，也能找出稿件、看清将改回哪些字，并在恢复后重新找到今天的内容。

**结果：恢复可完成，查找有障碍。** 活动稿的路径是「版本历史 → 选一行比较 → 该行 ⋯ → 恢复… → 恢复为新版本」。右栏已展开时可直接点「版本历史」。右栏收起时须先从「讨论与版本」进入；在 450 像素及以下，其可见文字也收起，只留下对话图标。版本列表以长编号为第一行，名称是小字。用 `V20261117161024 · 断网实验` 检查搜索，输入「断网实验」「20261117」命中，「昨天」「11月17日」均未命中。搜索只检查已渲染的行，折叠的自动备份不会出现在结果里。

恢复本身值得保留。确认前能预览将发生的差异，确认后先留当前内容，再把旧内容另存为新版本。隔离样例中，初稿、恢复前稿和恢复生成的新稿三份都在。

**建议。** 让文章菜单直接提供「版本历史」。行标题用作者认得的名字，如「断网实验」，旁边显示「昨天 16:10」。按日期分组就足以支持扫描；有匹配的折叠备份时给出「自动备份中另有 1 份」，点击再展开。保留比较与恢复确认，长版本号放到详情中。

## 下一版稿纸

保留现在的中文排版、正文行宽、短暂的正常保存反馈和失败时持续可见的救援入口。第一次写作只展开稿纸，顶栏给出「文章库」「讨论」以及当前文章的更多操作。再次打开时沿用作者上次的布局。

文章库优先支持搜标题、搜标签和新建。本文大纲从稿纸标题进入，跨文章资料通过素材选择器引用。讨论栏负责当前问题、引用和候选，文类与长期记忆分别回到文章设置、个人偏好。导出文件和发布博客各自进入相应预览。这样可以减少默认可见的操作，同时给找稿、写作和交付各留一条明确路径。

范围上优先合并「暂时搁置」与「归档」，去掉面向作者的停笔存版参数。多文类风格档案、观点演变管理可以后移，先保留一份可编辑偏好和带出处、可撤回的跨文章经验。以上是对 [V1 范围](../product/v1-scope.md) 的取舍建议。
