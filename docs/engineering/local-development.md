# 本地开发与检查

更新于 2026-11-23。适用于 C04 技术写作台，包含工作空间接入、文章库、正文自动保存、草稿与版本恢复、技术格式、本地图片和文件导入。[技术编辑器规格](../../openspec/specs/technical-editor/spec.md)

## 环境与安装

Node 版本见仓库 `.node-version`（22.22.2），pnpm 版本由 package.json 的 packageManager 固定（10.34.9）。先用本机版本管理器切换到该 Node，再执行：

```bash
node --version
corepack pnpm install --frozen-lockfile
corepack pnpm start
```

安装完成后，`start` 一次完成构建与启动，打开终端输出的“打开工作台”链接（包含一次性凭证，交换后地址会自动清除凭证）。Ctrl+C 停止，关闭浏览器页面不停止服务。无需模型、数据库或其他服务账号。

若没有 Corepack，可按 pnpm 官方安装方法安装 packageManager 指定版本，然后使用等价的 `pnpm` 命令。仓库不修改系统 Node 或全局包管理器配置。

默认端口被占用时会明确失败，不自动切换。可以先停止原服务，或者显式运行 `PORT=4320 corepack pnpm start`。服务只绑定 127.0.0.1；不开放局域网访问。PORT=0 主要供进程测试取得独立端口，实际地址以启动输出为准。

## 工作空间与本机接入

默认数据目录为 `~/Library/Application Support/Inkling/workspaces/default/`，不在源码仓库内。当前 SQLite 保存工作空间身份、正文与内部修订。连接工作空间后，首次点击“开始写作”；看到“已保存”后可重开。SQLite 嵌入应用进程，无需独立数据库服务。

不同端口也不能让两个服务同时写同一目录。程序正常退出或崩溃后 SQLite 释放锁；遇到不兼容、损坏或符号链接时拒绝打开，不会自动清空原数据。

需要独立开发空间时，可设置 `INKLING_WORKSPACE=/absolute/path corepack pnpm start`。同样的路径用于重新获取访问链接：

```bash
corepack pnpm local:access
# 自定义工作空间时
corepack pnpm local:access --workspace /absolute/path
```

一次性链接 5 分钟内有效，会话 12 小时有效；服务重启后重新接入。访问信息仅保存在权限受限的 runtime-access.json，本机管理入口拒绝浏览器跨源请求。不要分享访问链接或此文件。切换端口或浏览器会改变浏览器恢复副本所在的 origin，服务端数据目录不随之改变。

better-sqlite3 是原生依赖，pnpm-workspace.yaml 已允许其构建。若安装需从源码编译，Mac 需要 Xcode Command Line Tools；本机已验证编译成功。构建后的服务保留原生驱动作为外部依赖，因此不能只复制 dist 而遗漏锁定安装的运行依赖。

## 当前保存交互

编辑停顿约 1.2 秒自动保存，持续输入最多约 10 秒触发一次；也可按 Cmd/Ctrl+S。标题和正文的组合输入期间暂停提交。标题限制 200 个 Unicode code points（例如一个组合 emoji 可能包含多个 code points），超限时保留输入并提示修改。

“已保存”表示当前输入已核对服务端提交；响应丢失时先查询原请求和最新版本，再决定重试。保存期间继续输入不会被旧响应覆盖或误标为已保存。另一标签页抢先提交会阻止普通保存覆盖，可用“查看冲突”核对两边内容，再在正文编辑器中整理合并稿。

## 从文件导入文章

在文章库点「从文件导入」，选择 UTF-8 的 `.txt` 或 `.md` 文件，预览后点「确认导入」。第一版即包含整篇正文。纯文本按行保留空段与缩进。Markdown 采用首个一级标题作稿名，没有一级标题时沿用文件名。表格、公式和 Mermaid 流程图导入后可编辑。外部图片、HTML 或无法转换的片段会标出行号，并保存在可读的源码块中。单文件与转换后的主稿各限 2 MiB。

## 草稿恢复与救援

工作台加载后，即使本地服务停止，仍可继续输入。看到“浏览器恢复副本已更新”才表示最新输入已完成 IndexedDB 事务；它不等同于正文“已保存”。副本按工作空间、文章与标签页隔离，复制标签页也不会共享写入身份。

服务恢复后可按“重试保存”。如果服务重启导致会话失效，先用 `local:access` 取得新链接，在原页面打开后再重试；重新认证不会替换当前输入。重新打开页面时列出恢复副本，按时间和预览明确选择，再核对未决请求和服务器最新版本；有版本冲突则保留草稿并暂停普通保存。

不采用某份副本时，可以选择“保留副本，使用服务器版本”，原副本继续留在浏览器内；它会在下次打开时再次出现。已恢复且确认复制成功的非活动来源副本会被清理，其他标签页的副本保留。

冲突比较会显示本页草稿与已查看的服务器版本，标题、文字、纯格式/结构差异分别提示。比较不会替换正文，也不会自动拼接两份内容。整理完主编辑器后，选择“准备保存合并稿”再确认；继续输入或组合输入会使确认失效，另一标签页再次保存则会要求重新比较。也可以保留本页草稿后使用服务器版本；副本写入失败时停止切换，保留内存输入供救援下载。

恢复列表可“放弃此副本”，二次确认只删除这份浏览器副本，不撤回服务器提交。活动的其他标签页不允许删除；确认过程中记录被更新，也需重新查看后再决定。未选择的其他副本不受影响。

浏览器副本不可用、空间不足或事务失败时会明确提示；在线保存仍可使用，但未保存输入只在本页内存。离开前可点击“下载备份”，得到包含最新标题、正文、确认基线和未决请求的 JSON；恢复列表也可单独下载某一副本。救援稿不含访问凭证，不是 Markdown 导出或整个工作空间备份，当前也没有救援 JSON 导入界面。

若某份草稿包含当前编辑器无法识别的内容，点击“下载原始副本”可取得这篇文章所有无法识别的浏览器记录。JSON 保留原始节点、属性、确认基线和未决请求，图片引用仍指向当前工作空间。同一篇文章中可识别的副本仍可单独恢复。

恢复副本属于当前浏览器及地址（origin）。更换浏览器/端口、清除网站数据或浏览器主动回收数据会使其不可用，重要输入仍应完成服务器保存或下载。应用不是离线安装的 PWA：服务停止期间刷新不能打开工作台，重启服务并重新接入后才可选择已有副本。

## 开发模式

```bash
corepack pnpm dev
```

同时启动 Vite（4317）与 Node 开发服务（4318），Vite 代理 `/api` 请求。Ctrl+C 停止两个开发进程。`start` 使用一个服务提供构建页面与 API，与开发模式不同；验收使用构建产物，避免只验证开发服务器。

## 检查入口

```bash
corepack pnpm verify
corepack pnpm exec playwright install chromium
corepack pnpm test:e2e
```

verify 依次执行格式、lint、类型、依赖边界、构建、API/进程/架构测试、Harness 回归、文档和 OpenSpec 检查。浏览器测试为每个测试启动独立的临时端口服务与工作空间，结束后关闭并清理，不复用已有实例或接触个人默认目录。首次使用需安装对应 Chromium；Linux CI 安装时加 `--with-deps`。

有针对性地定位问题时可以运行：

| 命令 | 检查内容 |
| --- | --- |
| `corepack pnpm typecheck` | TypeScript strict |
| `corepack pnpm lint` | TypeScript 与 React Hooks 规则 |
| `corepack pnpm format:check` | 新工程源码和配置格式，不改历史原型 |
| `corepack pnpm check:architecture` | 越层、跨包内部和循环依赖 |
| `corepack pnpm test:storage-performance` | 隔离临时工作空间的真实保存 API / 服务端事件循环性能，门槛针对本机 Mac |
| `corepack pnpm test` | API、构建进程、架构正负例；进程测试前先 build |
| `corepack pnpm check:docs` | 本地文档路径与 docs 根目录规则 |
| `corepack pnpm check:specs` | 当前规格/变更与历史任务校验、单 active change |

GitHub Actions 复用 verify 和 E2E，不调用模型、不发布应用。CI 运行结果与本地验证分别记录。

## 模块与工具选择

当前有 `apps/web`、`apps/server`、`packages/contracts` 和 `packages/adapters`。contracts 导出健康响应 schema，web 校验真实响应，server 提供它；工作空间存储已放入 packages/adapters，正文用例已进入 packages/core。

React 19 与 Muya 0.2.0 提供编辑，Vite 8 构建 Web，Fastify 5 提供本机服务，esbuild 打包服务入口，Zod 4 负责契约。完整精确版本见各 package.json 和 pnpm-lock.yaml。TypeScript 使用 6.0.3：当前 typescript-eslint 的支持范围小于 6.1，因此没有机械采用 TypeScript 7。

dependency-cruiser 使用 package.json 的 workspaces 识别公开包导入；pnpm 使用 pnpm-workspace.yaml 安装。增减包分组时同步两处，架构正例会读取真实 workspaces 配置。内部包必须通过 exports 的公开入口访问；禁止相对路径跨包钻入 src。

依赖新增或升级按 change 处理，不在日常启动时追踪 latest。OpenSpec 1.16.1 现在也是项目锁定的开发依赖。

## 当前限制

正文支持在线自动保存、浏览器恢复副本和显式冲突合并。文章库可以导入文本和 Markdown 主稿。模型与发布仍在规划中。健康接口显示本地服务连通性，稿纸单独显示保存与副本状态。

浏览器测试覆盖中文文本及组合事件，不能代替真实中文输入法候选窗验证。构建会提示编辑器主包较大，这一条 bootstrap 尚未做加载性能优化。SQLite 存储选择已完成 POC；模型框架仍待验证。

## 版本历史

在右上角“⋯”打开“版本历史”。“保存版本”保留点击时的稿件，已有版本名称会保留。默认列出初稿、手动保留及恢复的版本，自动备份按需展开。用搜索框按日期、名称或版本号过滤，点行末“比较”对照当前稿，也可切换到另一个已存版本。行末“⋯ → 命名”可编辑名称，“恢复…”先用增删行展示当前稿恢复到所选版本的改动，点“恢复为新版本”后才提交。恢复保留所有历史；必须先保存当前稿，继续输入/选词会使旧确认失效。恢复响应未知时通过正文的“重试保存”核对，刷新后通过草稿恢复入口继续。等待恢复期间继续输入会保留这些输入并要求比较。

### 恢复点与输入法手工检查

默认历史显示初始版本、首次有变化的保存、距上一个自动恢复点满五分钟后发生变化的下一次保存，以及每次明确恢复产生的新版本。没有内容变化的保存不增加修订，也不推进恢复点时间；命名只增加版本标签。

```bash

```

打开该终端打印的访问链接，创建测试稿件；结束时 Ctrl+C 停止该测试服务。已有旧版服务需要重启才会使用新的版本 API，刷新网页本身不会更新服务端代码。

1. 切换 macOS 拼音输入法，在标题和正文分别连续输入，保持候选窗打开超过两秒，按 ⌘S；应保持候选窗、焦点和输入，不显示这段候选内容已保存。选词结束后应正常保存，刷新后完整保留。
2. 在浏览器开发者工具 Network 中启用慢速网络模拟，输入一段并等待“保存中”，立即开始第二段拼音，保持候选窗。旧保存响应到达时，候选窗与新输入不应被替换，也不应误显示新内容已保存。选词结束后保存，再恢复正常网络设置。
3. 保存两版，打开“查看并恢复版本”，再开始拼音选词。结束选词后尝试确认旧恢复，应要求重新查看和确认，新输入保留。
4. 记录 macOS/浏览器/输入法版本和上述各项结果；若失败，记录动作顺序与画面，不把自动组合事件通过代替该检查。

## 存储故障、损坏和容量

数据库写入失败时，“尚未保存”和浏览器副本/救援下载仍保留当前输入；错误恢复后按原请求核对再重试。历史达到 64 MiB 提示占用；超过 256 MiB 的新增正文版本会被拒绝，但命名、无正文变化的保存及已提交请求重放仍可用，不自动删除历史。该计数是累计修订正文大小，不是整个数据库文件的磁盘占用。

工作空间打开时逐版校验已有正文，发现内容损坏会隔离该文章。可以在“稿件需要检查”面板列出旧版本并下载经校验的 JSON；不会自动替换正文。结构性数据库损坏时服务拒绝启动，保留原文件，不保证所有损坏情况都能救援。下载文件当前没有导入界面，不能当作完整工作空间备份。

性能命令使用测试数据和临时目录，结束自动清理，不访问默认个人稿件。默认不在普通 verify 中运行目标 Mac 的耗时门槛；运行结果与限制见[存储性能记录](../validation/article-storage-performance.md)。

## C03 文章库

C03 使用 schema 3 支持多文章写作。文章库已接通安全切换、重命名、标签整理、查找、归档、回收站与编辑位置恢复。[文章库规格](../../openspec/specs/article-library/spec.md)

首次打开已有 schema 2 空间会在独占事务中增加文章库/标签元数据表和索引，回填当前标题，保留既有正文、修订、命名和去重记录；迁移或完整性检查失败会回滚。旧版 C02 程序不支持 schema 3，不能直接用旧程序打开升级后的目录；当前不提供自动降级。验收只使用临时工作空间，不修改作者个人稿件。

`POST /api/articles` 接收 mutationId 和可选 title，新请求建立独立稿件，重放不重复创建或改变后来选择的稿件。`GET /api/articles` 默认返回活动文章元数据，可用 state=active/archived/trashed 查看对应状态，以创建时间和 ID 倒序分页；limit 默认为 20、最大 100，beforeCreatedAt/beforeId 必须成对。不返回全文；可用 q 查找标题字面片段，用 tag 精确筛选标签，两条件取交集。标题投影与正文保存、版本恢复同事务更新，正文标题仍是唯一权威。

实现计划和实际步骤见 [C03 进度](../../openspec/changes/archive/2026-11-18-manage-article-library/progress.md)。


### 使用文章库与安全切换

启动本地服务后，点击工作台顶部“文章库”。点“新建”直接进入空白正文，也可打开已有稿；空标题显示“未命名文章”。列表每次加载 20 篇，“加载更多文章”追加下一页，搜索选项中的“刷新文章库”回到最新列表。桌面与窄屏均可收起面板，列表失败不会清空正文。

切换前有未确认输入时，选择“保存后切换”或“保留草稿并切换”。保存请求尚未结束时等待结束再操作；保存结果未知、冲突或待恢复副本可显式保留后离开。返回有副本的文章需选择“恢复此草稿”，不会自动用副本覆盖服务器正文。浏览器副本写入失败会阻止离开，仍可下载救援稿。打开失败保留原稿；结果未知时点击“重试切换”，不会重复新建。

切换期间会暂时锁定标题与正文，成功后进入独立文章会话；其他标签打开另一篇文章不会强制改变本页。初次打开/刷新页面仍采用工作空间记录的最近文章。

作者已在 Mac 上确认，标题或正文选词期间尝试新建、切稿、归档或移入回收站，原稿和输入保留。在重命名、标签和搜索框中按回车选词，表单没有提前提交。[手工验收记录](../../openspec/changes/archive/2026-11-18-manage-article-library/evidence/manual-ime-mac.log)

### 重命名与标签

在文章行末“⋯”里分别选“重命名”或“编辑标签”。保存成功后回到原筛选；关闭窗口可放弃本次输入。整理其他稿件时停留在当前文章。其他稿件改名使用其自身的正文和修订基线；并发冲突时保留拟议标题，需重新打开核对。新标题通过原有正文保存协议提交，保留本页最新正文；若已发生冲突或有保存结果待核对，应先在正文提示中处理。输入法选词期间不能提交重命名。

标签一行一个，去首尾空白和重复项，最多 10 个、每个 1–30 个字符；留空可清除。标签使用独立版本，不新增正文修订。“核对并重试标签”处理结果未知的请求，继续输入的标签仍保留。遇到其他页更新时展示服务器最新标签，使用“放弃输入并载入最新标签”后再编辑提交，不会自动覆盖他页修改。

整理期间先完成或明确放弃表单输入，再关闭面板切换文章；未知标签结果需先核对。未提交的整理表单只保留在当前页面，刷新/离开前有提示，不提供崩溃后恢复；正文草稿继续使用已有浏览器恢复协议。

验证时按 `corepack pnpm verify && corepack pnpm test:e2e` 串行执行：两者均会重建 `apps/web/dist`，并行运行可能在测试服务读取静态文件时清空目录，造成首页 404。进程或浏览器测试使用临时工作空间，不与个人服务共用数据。


### 标题查找与标签筛选

在“搜标题或标签”里输入文字即可按标题或标签片段查找，系统选词期间保留原结果。“全部文章”包含写作中和已归档的稿件。篇数表示当前条件下的总量。在搜索框右侧打开“搜索选项”，可组合标题片段与精确标签并点“查找文章”。标题按原样片段匹配，中文可用，ASCII 大小写不敏感，百分号/下划线等不作通配符；标签用完整名称、区分大小写。标题条件最多 100 个字符，标签最多 30 个字符。不搜索正文。

列表下方显示实际已应用的条件；尚未提交的新输入不会改变刷新和下一页所用条件。更换条件从第一页开始，“清除筛选”返回全部活动文章。无匹配和读取失败分别显示，失败可重试，当前正文和整理表单不受影响。选词期间不会提交或清除筛选，结束后需重新点击。

### 归档、回收站与只读

每篇文章行末的“⋯”提供“归档”或“取消归档”，以及“移入回收站”。整理其他稿件时不会切换正文。归档后保留正文和历史，可只读查看、比较版本；标题、正文、格式和版本写入禁用。文章库可切换“写作中／全部文章／已归档／回收站”，标题和标签查找作用于当前状态；换状态从第一页开始。

移入回收站前需确认；“取消操作”不改变文章。确认时有未保存输入可选择保存后操作，或“保留草稿并…”；浏览器副本未能可靠写入时会阻止操作，仍可下载救援稿。归档后的未选副本保留并可下载，取消归档后才允许恢复到编辑器。回收站不提供正文打开或永久删除；点击“恢复”并确认后，回到移入前的活动或归档状态，不复制文章。当前稿移入回收站后打开最近可用稿；无稿件时进入“开始写作”空态，不自动创建空文章。

确认框打开后其他标签改变状态或标签，旧确认会被拒绝，需取消并重新查看，不自动采用新基线。结果未知时使用“核对并重试”；若之后继续写过内容，可选择“保留草稿并核对”。已提交操作的后续打开失败不会重复执行归档/删除。状态操作完成会重新读取列表，保留状态视图、重置查找条件；以面板实际显示的筛选为准。

跨标签状态不会实时推送：新保存遇到归档/回收站会被服务端拒绝，本页输入和副本保留；也可点“搜索选项 → 刷新文章库”核对当前稿件的编辑权限。只读或状态未知时可在正文区域点“核对文章状态”，核对只改变编辑权限，不替换正文。状态读取失败会暂停编辑，重新核对成功后才能继续；另页取消归档后核对状态，再按原保存提示处理未确认输入。选词期间先完成中文输入，再重新操作。

### 编辑位置恢复

同一浏览器中再次打开同一文章、同一已保存版本时，恢复正文选择和相对正文的阅读滚动位置；不自动抢走输入焦点。新版本、非法坐标或跨文章记录回到文首，短文滚动受窗口可滚范围限制。打开后已经开始操作时，不再用迟到的恢复动作回跳。

位置记录使用 localStorage，按工作空间/文章隔离，不包含正文、不新增文章版本。正文保存成功后位置跟随新修订；未确认输入、冲突或待选择恢复副本不套用旧坐标。位置存储被禁用或容量不足时会提示“编辑位置无法保留，正文保存不受影响”，仍可继续保存与切换。它是浏览器便利记录，不属于文章备份，也不支持跨设备同步。
